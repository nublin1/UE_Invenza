# Настройка управления Invenza

Язык: **Русский** | [English](../en/InputConfiguration.md)

Динамическая справка по F6 описана в [отдельном разделе](ControlsHelp.md). Настройка сохранения и собственных команд загрузки приведена в [руководстве по сохранению](InventorySaving.md).

Подробное дополнение к разделу 8 [общего описания](GettingStartedOverview.md). Перед настройкой управления подключите `InventoryCollectionComponent`, `UIInventoryManager` и интерфейс по [руководству интеграции](ProjectIntegration.md).

Описание привязок сверено с текущим C++-кодом. Клавиши ниже — пример для собственного проекта; реальные значения Mapping Context и настройки готовых Blueprint нужно проверить в редакторе.

## 8.1. Где задаётся управление

В Invenza используются три места настройки:

| Место | Назначение |
|---|---|
| `UIInventoryManager → UISettings` | Действия открытия окон, модификаторы переноса, поворот предмета и кнопки мыши |
| Input Mapping Context | Соответствие клавиш и Input Actions |
| `InteractionComponent → KeyBindings` | Связь Input Action с основным или дополнительным действием объекта |

Input Action обозначает действие, а Mapping Context связывает его с физическим вводом. Контекст должен быть добавлен в Enhanced Input Local Player Subsystem. Эти понятия и состояния событий описаны в [документации Enhanced Input для UE 5.6](https://dev.epicgames.com/documentation/en-us/unreal-engine/enhanced-input-in-unreal-engine?application_version=5.6).

Привязки управления инвентарём находятся в `UISettings` менеджера персонажа.
В общем Data Asset `InvenzaSettings → Controls Help` настраивается
[модальная справка по текущим клавишам](ControlsHelp.md), открываемая по F6.

## 8.2. Подготовка Enhanced Input

Включите Enhanced Input и проверьте в Project Settings → Input классы `EnhancedPlayerInput` и `EnhancedInputComponent`.

Для стартовой конфигурации можно использовать Input Actions из плагина. Если создаёте свои действия для кнопок, выбирайте Value Type = Boolean и начинайте с обычного нажатия без дополнительных Hold, Tap или Chorded-триггеров. При замене ассета назначьте одну и ту же Input Action и в контексте, и в настройках компонента.

Контекст инвентаря менеджер добавляет автоматически с приоритетом 1. Контекст перемещения персонажа и отдельный контекст взаимодействия подключаются вашей игровой логикой. `InteractionComponent` сам не добавляет Mapping Context.

Согласуйте клавиши с существующим управлением проекта. При пересечении действий проверьте приоритеты контекстов и Consume Input, а затем оба действия в игре. Один только приоритет контекста не гарантирует нужное поведение всей цепочки обработчиков.

## 8.3. Действия инвентаря

Откройте Blueprint персонажа, выберите `UIInventoryManager` и раскройте `UISettings`. Назначьте следующие поля:

| Поле | Ассет из плагина | Назначение |
|---|---|---|
| `InventoryMappingContext` | `Input/InputMappingInventoryContext` | Контекст клавиш инвентаря |
| `ToggleInventoryAction` | `Input/UIActions/IA_ToggleInventory` | Открытие и закрытие интерфейса инвентаря |
| `ToggleCraftAction` | `Input/UIActions/IA_ToggleCraftMenu` | Переключение состояния крафта персонажа |
| `IA_Mod_QuickGrab` | `Input/UIActions/IA_QuickGrab` | Модификатор быстрого переноса выбранного предмета |
| `IA_Mod_GrabAllSame` | `Input/UIActions/IA_GrabAllSame` | Модификатор переноса однотипных предметов |
| `IA_RotateDraggedItem` | `Input/UIActions/IA_RotateItem` | Поворот предмета во время перетаскивания |

Откройте выбранный Mapping Context и задайте клавиши. Например:

| Действие | Пример клавиши |
|---|---|
| Открытие инвентаря | `I` |
| Крафт персонажа | `C` |
| Быстрый перенос | удержание `Left Shift` |
| Перенос однотипных предметов | удержание `Left Ctrl` |
| Поворот предмета | `R` во время перетаскивания |

Менеджер обрабатывает открытие окон и поворот по `Started`, а модификаторы включает по `Started` и выключает по `Completed`. Для базовой конфигурации используйте простые кнопочные действия. Если вводите сложные триггеры, дополнительно проверьте отпускание и отмену: в текущих привязках модификаторов обработчика `Canceled` нет.

Поле `ToggleEquipmentAction` и ассет `IA_ToggleEquipment` существуют, но `InitializeBindings` менеджера сейчас не связывает это поле с обработчиком. Для отдельной клавиши экипировки понадобится собственная привязка к открытию её UI.

`ToggleCraftAction` работает с подключённым `CraftingComponent` персонажа. При активном взаимодействии с крафтовой станцией обработчик не переключает крафт персонажа. Отображение окна зависит от подключённого UI и его логики.

## 8.4. Кнопки мыши

Кнопки выбора, использования и контекстного меню задаются непосредственно как `FKey` в `UISettings`. Для них не нужно создавать Input Actions.

| Поле | Назначение | Значение для первого запуска |
|---|---|---|
| `ItemSelectKey` | Выбор и начало перетаскивания | Left Mouse Button |
| `ItemUseKey` | Использование предмета | Right Mouse Button |
| `ItemMenuKey` | Запрос контекстного меню | Middle Mouse Button |

Левая и правая кнопки заданы конструктором настроек. Для `ItemMenuKey` явного значения по умолчанию в конструкторе нет — назначьте его в Blueprint. Средняя кнопка в таблице предложена как отдельная клавиша для тестирования.

В сеточном UI проверка использования выполняется раньше проверки меню. Если назначить одну кнопку на оба действия и использование разрешено, меню может не открыться. Для списка также не следует совмещать эти назначения: обработчик может выполнить обе операции.

Использование предметов зависит от `bAllowItemUsage` инвентаря и реализации `UseItem` у предмета. Привязка кнопки сама по себе не задаёт лечение, применение оружия или другую игровую механику.

## 8.5. Быстрый перенос и поворот

Быстрый перенос выполняется при нажатии `ItemSelectKey` с активным модификатором. Без модификаторов эта кнопка запускает обычное перетаскивание.

Для проверки откройте контейнер или другой доступный целевой инвентарь, удерживайте клавишу быстрого переноса и нажмите на предмет. Затем повторите с модификатором однотипных предметов. Результат зависит от доступного назначения, ограничений размещения и свободного места.

Если оба модификатора активны одновременно, текущие обработчики сетки и списка сначала проверяют быстрый перенос одного предмета. Для предсказуемого управления назначьте модификаторам разные клавиши.

Поворот срабатывает только при активном перетаскивании через `ItemDragDropOperation`. Для проверки используйте прямоугольный предмет, например размером 2 × 1, и сетку, учитывающую размеры предметов. Нажатие клавиши вне перетаскивания не поворачивает предмет в инвентаре.

## 8.6. Взаимодействие с объектами мира

В `InteractionComponent → KeyBindings` добавьте две записи, если нужны оба типа взаимодействия:

| Action | Type | Пример клавиши в контексте |
|---|---|---|
| `Input/Actions/IA_PrimaryIteract` | `Primary` | `E` |
| `Input/Actions/IA_SecondaryIteract` | `Secondary` | `F` |

Имена `Iteract` приведены как в текущих ассетах плагина. Эти Input Actions должны присутствовать в активном Mapping Context. Можно добавить их в собственный игровой контекст или использовать `GameplayMappingContext`, проверив его состав и добавление к локальному игроку.

Компонент начинает взаимодействие по `Started` и завершает его по `Completed`. Удержание и длительность взаимодействия задаются в данных действия интерактивного объекта. Для первого подключения не добавляйте Hold-триггер поверх этой логики.

Проверьте камеру персонажа, `TraceChannel`, расстояние трассировки и коллизию объекта. Наличие Input Action не поможет, если компонент не обнаруживает объект. Значение кнопки определяет тип взаимодействия, а фактическое действие — подбор, открытие или работа на станции — задаётся компонентом объекта.

## 8.7. Горячие клавиши слотов

Слоты сеточного инвентаря могут иметь `UseAction`. Менеджер перебирает доступные слоты и привязывает их действия к использованию соответствующего слота.

Для панели быстрого доступа назначьте Input Actions нужным слотам и добавьте их в активный Mapping Context. В плагине есть `IA_HotkeySelect_1`–`IA_HotkeySelect_8`, которые можно связать с клавишами `1`–`8`.

Для готовой сетки проверьте, что назначенные слоту действия попадают в собранные данные слотов. При собственной генерации слотов заполните `UseAction` в их данных. Если слоты появляются или меняются после начальной привязки ввода, требуется отдельно согласовать обновление привязок в реализации.

## 8.8. Курсор, фокус и проверка управления

`UIInputModeSubsystem` переключает режим между Game Only и Game and UI, а также видимость курсора по запросам владельцев UI. При подключении собственного меню согласуйте его управление курсором и режимом ввода с этой подсистемой.

Для проверки базового управления:

1. Запустите PIE и нажмите на игровое окно, чтобы оно получило фокус.
2. Откройте и закройте инвентарь. Проверьте курсор и возврат управления персонажем.
3. Перетащите предмет, затем проверьте его поворот и размещение.
4. Проверьте быстрый перенос и отпускание каждого модификатора. После отпускания обычное перетаскивание должно снова работать.
5. Проверьте разные кнопки использования и контекстного меню.
6. Проверьте основное и дополнительное взаимодействие с объектом, включая удержание, если оно настроено.
7. Если есть панель быстрого доступа, проверьте действие каждой назначенной клавиши.

При отсутствии реакции сначала проверьте назначение Input Action, её наличие в активном контексте и используемый Input Component. Менеджер инвентаря привязывает действия к PlayerController с индексом 0, а взаимодействие — к Input Component локально управляемого персонажа. Эта реализация требует отдельной адаптации для нескольких локальных игроков.
