# Подбор нескольких предметов и разбор коробки

Пример: `/InventorySystemInvenzaPlugin/Blueprints/Examples/Pickups/BP_ScrapBox`.
Перетащите Blueprint на уровень, наведитесь на коробку и удерживайте основное действие две секунды.
Подсказка «Разобрать» меняется на «Разбираем…». Отпускание до завершения отменяет разбор.
После завершения выдаются `Board ×2`, `Rope ×1`, `IronIngot ×1` из общей `DT_ItemData`.

В `PickupComponent`:

- `InitialItems`: список строк предметов и количества. Непустой список включает режим набора; `InitialItem` используется только для прежнего одиночного подбора.
- `MeshSource = CustomMesh`: отдельные `CustomMesh`, `CustomMaterials`, `CustomMeshScale`. Пример использует уже существующий меш коробки.
- `MeshSource = FirstItem`: меш, материалы и масштаб первого предмета набора. Содержимое набора от этого выбора не меняется.
- `VisualMeshComponent`: компонент, внешний вид которого меняет подбор; без выбора используется первый Static Mesh актора.
- `OverflowDropOffset`: локальное смещение для выпадающих остатков. Общий `PickupClass` должен создавать актор с `PickupComponent`.
- `InteractableDataMap → Primary`: редактируемые название, действие, активное действие, `bHoldToInteract` и `InteractableDuration`. Тексты примера находятся в `ST_PickupExamples` рядом с Blueprint.

Набор использует `GetReceivingInventories`: сначала основной рюкзак, затем собственные обычные хранилища с `bReceiveGrantedItems = true`. Классы виджетов и `bOpenWithExternalInventory` не влияют на получение. Экипировка, хотбар, торговые и служебные инвентари не используются. Учитываются вес, размеры и стаки. Количества выше максимума стака разделяются без потери.

Всё, что не поместилось, выбрасывается отдельными обычными предметами. Если принимающих хранилищ нет, весь набор оказывается на земле. Исходная коробка уничтожается после обработки. Если создать выпавший предмет не удалось, остаток удаляется, коробка всё равно уничтожается, а в лог выводится ошибка с предметом, количеством и идентификатором. Повторной выдачи нет.

Из Blueprint можно вызвать `InitializeItems` на сервере для задания набора созданному актору. Инициализация сохраняется между загрузками вместе с каждым предметом; подбор и уничтожение выполняет сервер. У актора примера включена репликация. Старый `InitializeDrop` и одиночный формат сохранений поддерживаются.

Длительность удержания контролирует серверная сессия Begin/Cancel/Complete. Запрос завершения не сокращает серверный интервал; сервер проверяет отмену, расстояние, эксклюзивный доступ и повторное завершение. Прямой RPC менеджера инвентаря не обходит эту сессию. Серверный NPC может начать тот же протокол через `UInteractionComponent::RequestInteraction`. Незавершённая сессия истекает после длительности удержания плюс `CompletionRequestGracePeriod`.
