# Primary Layout и диагностика слоёв

Язык: **Русский** | [English](../en/UILayout.md)

`WBP_PrimaryLayout` содержит четыре слоя: `UI.Layer.Game` — игровой HUD, `UI.Layer.GameMenu` — инвентари и крафт, `UI.Layer.Menu` — общее меню, `UI.Layer.Modal` — модальные окна. Их визуальный порядок задаётся в Overlay этого Widget Blueprint. Регистрация слоёв находится в Class Defaults → `LayerDefinitions`: тег и имя существующего виджета слоя. Отладчик читает этот реестр; отдельно назначать ему четыре ссылки не нужно.

## Экраны и вложенные окна

Слой хранит стек экранов на базе `UInvenzaBaseWidget`. В GameMenu обычно находится один экран `WBP_GameMenuInvenza`, а внутри него — несколько одновременно доступных инвентарей, крафт и окна взаимодействия. Их не нужно превращать в отдельные записи верхнего стека.

Стартовые классы экранов передаются через `InitialScreens`. Они добавляются один раз за время подключения layout к интерфейсу. Список `InitialCollapsedScreens` сохраняет существующую политику начального показа.

## Операции

- `PushContentToLayer(Tag, Class)` создаёт экран и помещает его в зарегистрированный слой.
- `UUILayer::PushWidget(Instance)` поднимает существующий экземпляр; повторная запись не создаётся. Разные экземпляры одного класса допустимы. Нельзя одновременно поместить один экземпляр в два слоя или использовать контроллер другого игрока.
- `PopContentFromLayer(Tag)` / `UUILayer::PopContent()` удаляет верхний экран и возвращает предыдущий. Повторный вызов для пустого стека безопасен.
- `RemoveContent(Instance)` удаляет именно указанный экран, в том числе из середины стека.
- `ClearLayer(Tag)` очищает один слой; `ClearAllLayersExcept(Tag)` сохраняет выбранный и очищает остальные; `ClearAllLayers()` очищает все зарегистрированные слои.

Неизвестный тег выводит предупреждение в лог. При неизвестном исключении `ClearAllLayersExcept` ничего не очищает. После последнего Pop и после Clear ссылка на верхний экран сбрасывается; при `bCollapseWhenStackIsEmpty` слой сворачивается. Для HUD можно оставить этот существующий флаг выключенным.

Обычное удаление и очистка используют общий путь деактивации, удаления из родителя, освобождения запросов UI-ввода и уведомления `OnRemovedFromLayer`. Для собственной логики доступны `OnLayerScreenActivated`, `OnLayerScreenDeactivated`, `OnRemovedFromLayer`. Запросы UI-ввода временно перекрытого экрана и его вложенных виджетов приостанавливаются и восстанавливаются при возвращении экрана. Удалённый экран не должен оставлять активные запросы ввода.

Закрывайте экран через API его слоя, а не отдельным `RemoveFromParent`, иначе запись стека останется. Внутриигровое общее меню открывается через зарегистрированный MenuLayer и удаляется из него тем же API. Клавиша **M** и отдельная стартовая карта меню сохраняются; см. [общее меню](FrontendMenu.md).

## Отладчик

Клавиша **U** переключает `WBP_LayersDebugger`. В нём четыре колонки, как в исходном виджете: **Game**, **Game Menu**, **Menu**, **Modal**. В каждой перечислены только названия экранов её стека, начиная с верхнего. Активный видимый экран выделяется золотым цветом; остальные имена серые. Пустой слой оставляет колонку пустой.

Отладчик получает данные из реального Primary Layout и обновляется по событиям стека и видимости. Он не меняет видимость или обработку мыши у проверяемых окон и не опрашивает их каждый Tick. Вложенные элементы инвентаря не выводятся отдельными техническими строками.

Разметка и заголовки остаются в `WBP_LayersDebugger`. Обычный цвет и шрифт задаются через `EntryStyle`, цвет активного имени — `ActiveColor` в Class Defaults. Строки используют существующий Core-виджет `WBP_LabelBaseText_Wrapped`.
