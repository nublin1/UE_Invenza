# Взять выбранное количество из хранилища

При открытом хранилище прежнее текстовое контекстное меню физического предмета содержит дополнительное действие **Take amount...** («Взять количество…»). Остальные доступные предмету действия сохраняются. В появившемся окне указываются **Take: N** и **Remaining: M**. После подтверждения ровно `N` единиц перемещаются в основной инвентарь взаимодействующего персонажа.

## Поведение

- Доступный диапазон — от одной единицы до свободного количества, включая весь стак. Зарезервированные единицы не доступны для переноса. `Remaining` показывает весь остаток в хранилище, включая резервы.
- Перенос не требует свободной ячейки для промежуточного разделения в хранилище. Частичный перенос работает и из полностью заполненного контейнера.
- Получатель — основной физический инвентарь владельца `UIInventoryManager`. Указанный клиентом другой получатель игнорируется.
- Сначала планируется размещение всего количества: объединение совместимых стаков, новые стаки, свободные и зарезервированные ячейки, лимит числа стаков и вес. Затем единым действием меняются источник и получатель. При отказе оба остаются прежними.
- Если места или допустимого веса недостаточно, окно остаётся открытым и предлагает выбрать меньшее количество. Если стак или его доступное количество изменились, требуется повторное подтверждение с обновлённым диапазоном.
- Перенос части создаёт предмет с отдельной идентичностью у получателя и сохраняет исходный предмет с остатком. Перенос всего стака удаляет его исходные ссылки. Класс предмета, метаданные и авторское состояние сохраняются; резервы и подписки исходного предмета не копируются.
- При открытом торговце действие не заменяет покупку. Хотбар и прочие ссылочные контейнеры не считаются физическим источником. Режим обмена экипировкой другого персонажа также использует прежние действия.

## Проверки сервера

`Server_TakeItemAmount` передаёт запрос на сервер владельца менеджера. Сервер повторно проверяет источник, слот и предмет, доступ и текущую блокировку взаимодействия, дистанцию, свободное количество, снимок количества из окна и вместимость основного инвентаря. Выбор в UI не предоставляет прав доступа.

`FItemMoveData::RequestedAmount` используется этим запросом. `0` сохраняет смысл старых переносов целого стака. Положительные количества следует отправлять через `FInventoryTakeAmountRequest` и `Server_TakeItemAmount`, а не через старый общий запрос перетаскивания. `HandleTakeAmount` — серверный метод для нативных интеграций.

Ошибка возвращается через `Client_TakeItemAmountResult`. Подтверждение ожидает результат сервера; повторное нажатие во время ожидания не создаёт второй запрос. Отмена закрывает окно без нового переноса. Уже выполненную сервером операцию закрытие окна не откатывает.

## Настройки и внешний вид

В `InvenzaSettings` добавлены:

- `InvContextModalActions[TakeAmount]` с шагом `RequiresAmount`;
- `ModalActions[TakeAmount]` с текстовой подписью;
- `ModalHeaderWidgets[InventoryTakeAmount]`;
- `TakeAmountMessages` с локализуемыми сообщениями об отказах.

Заголовок количества: `WBP_TakeAmountHeader`. Пункт выбора количества и остальные действия создаются прежним `WBP_Selection` через существующие текстовые кнопки. Для собственного инвентаря и внешнего хранилища используется одно и то же меню. Обычный интерфейс разделения стака не заменяется.

Все новые подписи находятся в `ST_InvenzaRuntimeTexts` под ключами `Invenza.TakeAmount.*`. Форматы счётчиков и текст ожидания назначены через редактируемые `FText`-свойства нового заголовка. Layout создан в Widget Blueprint.

Резервирование базового `UItemBase` теперь вычитает зарезервированное количество и реплицирует суммарный резерв для корректного диапазона на клиенте. Частичное освобождение сохраняет оставшийся резерв.
