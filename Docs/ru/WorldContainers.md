# Предметы и контейнеры в мире

Язык: **Русский** | [English](../en/WorldContainers.md)

Практическое дополнение к разделу 9 [общего описания](GettingStartedOverview.md). Предполагается, что персонаж уже имеет рабочие инвентарь, интерфейс и [управление](InputConfiguration.md). Настройки ниже сверены с исходниками; конкретные значения Blueprint-примеров проверяйте в редакторе.

## Выбор объекта

| Задача | Компонент или пример |
|---|---|
| Поднять предмет с земли | `PickupComponent`, пример `BP_ExamplePickup` |
| Открыть один сундук | `ContainerComponent` и `InventoryCollectionComponent` |
| Открыть несколько хранилищ вместе | [StorageAccessPoint](StorageAccessPoint.md) |
| Передавать вещи и менять экипировку NPC | [CharacterInventoryAccessComponent / манекен](CharacterInventoryExchange.md) |

## Подбираемый предмет

Для первого примера используйте `BP_ExamplePickup` из `Blueprints/Examples`. В его `PickupComponent` настройте `InitialItem`: выберите Data Table предметов, Row Name и `Amount`. Строка должна иметь структуру `FItemData`, а количество — быть больше нуля.

Проверьте меш предмета и коллизию для взаимодействия. Поставьте объект перед персонажем, наведите камеру и используйте основное действие. Предмет должен попасть в подходящий инвентарь с учётом размеров, вместимости и стаков. Проверяйте также отказ подбора при отсутствии места.

Для собственного актора добавьте `PickupComponent` и Static Mesh с подходящей коллизией. При создании через игровую логику компонент предоставляет `InitializeDrop` с записью `FInitItemsEntry`. Для выбрасывания из интерфейса отдельно назначьте подходящий `PickupClass` в общих настройках и разрешите `bIsDroppable` у предмета.

## Обычный контейнер

Создайте Blueprint Actor или используйте пример контейнера из `Blueprints/Examples/Containers`. Для собственного объекта добавьте `InventoryCollectionComponent`, `ContainerComponent` и меш с коллизией.

В `ContainerComponent` настройте:

1. `StartupInventories` — инвентари этого актора. Начните с одной записи сеточного инвентаря.
2. `InventoryTag` записи и `MainLootContainerInvTag` компонента — одинаковый тег основного открываемого инвентаря.
3. `ContainerTitle` — название для интерфейса и общего склада.
4. `InventoryClass`, размеры сетки, класс слота и классы виджетов. Для создания структуры без UI выберите `bCollectInvDataFromWidget = false`.
5. `StartItems` — строки таблицы и количество стартовых предметов.
6. Данные основного действия взаимодействия — открытие контейнера. При собственной конфигурации проверьте тип действия и текст подсказки.

Коллекция учитывает содержимое, а компонент контейнера создаёт инвентари и открывает доступ через взаимодействие. `UIInventoryManager` игрока отвечает за показ и перенос вещей; добавлять менеджер игрока на сундук не требуется.

`bDestroyWhenEmpty` позволяет уничтожать контейнер после опустошения основного loot-инвентаря. Для постоянного склада оставьте настройку выключенной. Если актор содержит несколько инвентарей, учитывайте, что проверка этого флага ориентируется на основной контейнер.

## Обнаружение, удержание и дистанция

На персонаже `InteractionComponent` задаёт канал и дальность трассировки. Меш или коллизия объекта должны блокировать этот канал. Привязка Input Action определяет Primary или Secondary, а данные объекта — фактическую операцию и необходимость удержания.

Не путайте дальность обнаружения с допустимой дистанцией активного взаимодействия. Общий `MaxInteractionDistance` задаётся в Data Asset настроек; точка доступа к складу дополнительно проверяет свой `MaxUseDistance`. Подробности: [дистанция взаимодействия](InteractionDistance.md).

## Подключение к общему складу

Чтобы обычный контейнер находился автоматически, он должен иметь `ContainerComponent` и зарегистрированные инвентари в `InventoryCollectionComponent`. Учитываются радиус и фильтры точки доступа. Для точного состава склада используйте явный список акторов.

После динамического создания контейнера обновите каталог на сервере. Само изменение содержимого уже подключённого инвентаря не требует повторного поиска акторов. Полная настройка: [общее окно хранилищ](StorageAccessPoint.md).

## Проверка

Проверьте открытие, двусторонний перенос, заполнение инвентаря, закрытие и повторное открытие. Для предметов с размером больше одной ячейки проверьте размещение у границ сетки. Для контейнера с уничтожением — опустошение и исчезновение объекта.

В сетевом проекте включите репликацию актора и используемых компонентов, затем проверьте операции с клиентского персонажа. Эти сценарии являются рекомендациями для проверки вашей конфигурации; запуск PIE и сетевых тестов в рамках написания этого документа не выполнялся.
