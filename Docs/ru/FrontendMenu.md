# Главное меню, настройки и сетевые сессии

Язык: **Русский** | [English](../en/FrontendMenu.md)

Карта: `/Game/Frontend/Maps/L_MainMenu`. Она назначена `GameDefaultMap`. Стартовая карта редактора остаётся прежней — `Map_Ex`; для просмотра меню откройте `Content/Frontend/Maps/L_MainMenu` и нажмите Play.

## Экраны и слои

`AFrontendMenuHUD` наследуется от `AGameHUD_Inz`, создаёт существующий `WBP_PrimaryLayout` и помещает `WBP_FrontendMenu` через `PushContentToLayer(UI.Layer.Menu, ...)` в третий слой. Игровые слои на этой карте свёрнуты. Главный экран содержит входы в сохранение, загрузку, настройки и сетевую игру. Каждый раздел — отдельный Widget Blueprint; Esc возвращает на главный экран. Подтверждение режима экрана остаётся внутри страницы настроек и завершается кнопкой либо таймером.

Новые ассеты находятся в `Content/Frontend`. `WBP_FrontendMenu`, `WBP_MenuButton`, `WBP_ServerRow` редактируются в UMG Designer. Экраны наследуются от `UInvenzaBaseWidget`, кнопки — от `UUIButton`, подписи используют `ULabelBaseText`. Исходные shared Widget Blueprint плагина не изменялись.

## Графика и аудио

`UInvenzaGameUserSettings` хранит разрешение, режим экрана, VSync, FPS, пресет качества и три уровня громкости в пользовательском `GameUserSettings.ini`. Применение нового разрешения/режима требует подтверждения за 15 секунд; отмена или таймер восстанавливают сохранённые настройки. Кнопка «По умолчанию» сначала меняет значения в форме — их нужно применить.

Звуковые классы: `SC_Master` → `SC_Music`, `SC_Effects`. `SM_UserSettings` применяет громкость при смене карты. По умолчанию новые звуки проекта относятся к Effects; для музыки укажите `SC_Music` в Sound Wave / Sound Cue. Ранее явно назначенные собственные Sound Class следует включить в эту иерархию, чтобы их затрагивала общая громкость. Демонстрационная музыка не добавлялась.

## LAN: тест на одном компьютере

По умолчанию используются `OnlineSubsystemNull` и `IpNetDriver`; вход в Steam не нужен. В двух терминалах PowerShell из корня проекта:

```powershell
.\Scripts\Launch-Frontend.ps1 -Profile LAN -WindowX 30 -Port 7777
.\Scripts\Launch-Frontend.ps1 -Profile LAN -WindowX 700 -Port 7779
```

В первом окне: «Сетевая игра» → название/число игроков → «Создать и играть». Во втором: «Найти / обновить» → выбрать найденную игру. Альтернатива — подключиться к `127.0.0.1:7777`. На другом компьютере локальной сети укажите IPv4 хоста. Windows Firewall должен разрешать игре локальный сетевой обмен; LAN-поиск использует UDP broadcast.

Хост открывает существующую `Map_Ex?listen`. В одиночной и сетевой игре клавиша **M** открывает общее меню без выхода из текущей игры; **«Продолжить игру»** закрывает его, **«В главное меню»** завершает сессию с сохранением. Функциональные клавиши для входа, сохранения, загрузки и выхода не назначаются. Сетевой разрыв возвращает клиента в меню с сообщением. Сетевой код находится в `UInvenzaSessionsSubsystem`, поэтому смена карты не теряет состояние операции.

Для быстрой проверки собственного сетевого кода можно отдельно использовать PIE: 2 игрока, New Editor Window, Play As Listen Server. Такой запуск автоматически соединяет игроков и не проверяет браузер сессий.

## Steam

Включены штатные плагины `OnlineSubsystemSteam` и `SteamSockets`. Профиль `Config/Custom/Steam/DefaultEngine.ini` использует `SteamSocketsNetDriver` и тестовый `SteamDevAppId=480`. Этот App ID общий; поиск добавляет проектный фильтр и повторно проверяет результаты. При недоступном Steam меню показывает ошибку, вместо незаметного создания LAN-сессии.

Запустите Steam и войдите в аккаунт, затем:

```powershell
.\Scripts\Launch-Frontend.ps1 -Profile Steam
```

Это standalone-запуск редакторного executable с `-game -CustomConfig=Steam`. Для проверки подключения через Steam используйте два компьютера и разные аккаунты с одинаковой версией проекта. Две локальные копии для разработки удобнее запускать в LAN.

Для **Development** сборки запускайте executable с `-CustomConfig=Steam`. Карты и папка Frontend добавлены в cook, каталог Steam-конфигурации — в staging. При ручном запуске packaged executable вне Steam при необходимости положите `steam_appid.txt` с `480` рядом с настоящим игровым executable в `Binaries/Win64`. Не включайте этот файл в дистрибутив Steam. Для выпуска замените 480 своим App ID и выберите Steam-профиль на этапе сборки; переключение CustomConfig через командную строку Shipping по умолчанию ограничено движком.

## Проверки и сопровождение

- `Invenza.Frontend.MenuFlow` — редакторная проверка слоя, навигации, отмены настроек, проверки IP и отмены поиска.
- `Invenza.Frontend.LANHost` / `LANClient` — запускать в двух отдельных `-game -nosteam` процессах с одинаковым уникальным `-FrontendTestRun=<id>`. Проверяют реальный поиск, подключение, смену карты и возврат после выхода хоста.
- `Invenza.Frontend.SteamLifecycle` — standalone с `-CustomConfig=Steam`: инициализация Steam, создание временной сессии, Steam Sockets transport и выход.
- `Scripts/UI/create_menu_hub.py` создаёт текущие страницы меню после сборки Editor target и удаляет старые назначения сохранения/загрузки. Старый `create_frontend.py` относится к первоначальной версии; для текущего меню используйте новый скрипт. Ручные изменения пересоздаваемых страниц при его запуске заменяются.
- `Scripts/UI/preview_frontend.py` сохраняет PNG трёх экранов в `Saved/Frontend`; запускать через `-ExecutePythonScript` полноценного редактора с `-RenderOffscreen`, не через Python commandlet.

Проверки сетевой корректности инвентаря не входят в эту работу. Для возврата между картами исправлено только время жизни его отложенной UI-инициализации: таймер привязан к UObject и отменяется в EndPlay.

Проверено 16.10.2026 на UE 5.6.1: сборка Development Editor, MenuFlow в PIE, два отдельных процесса LANHost/LANClient, SteamLifecycle с запущенным Steam и App ID 480 — успешно. Подключение двух разных Steam-аккаунтов и упаковка полной игры отдельно не проверялись. Превью проверены в 1440×960 и 1280×720.

## Страницы и настройки общего меню

- `/Game/Frontend/UI/WBP_FrontendMenu` — корневые кнопки и переключение разделов.
- `/Game/Frontend/UI/WBP_SettingsPage` — графика, звук и подтверждение режима экрана.
- `/Game/Frontend/UI/WBP_NetworkPage` — создание, поиск и подключение к сетевой игре.
- `/InventorySystemInvenzaPlugin/UI/SaveLoad/WBP_SaveGamePage` и `WBP_LoadGamePage` — отдельные страницы сохранения и загрузки.
- Вход в меню из игры: **M**, настройка `MenuKey` в **Project Settings → Invenza Main Menu → Input**. Старый `WBP_SessionBar` не добавляется на экран.

Класс корневого меню, клавиша входа, PrimaryLayout, игровой уровень и String Table назначаются в **Project Settings → Invenza Main Menu**. Подписи и тексты новых страниц находятся в `/Game/Frontend/Localization/ST_FrontendMenu`; исходные значения — `Scripts/UI/Data/FrontendMenuTexts.csv`. Размеры и оформление меняются в Designer. Списки режимов, качества, FPS и время подтверждения редактируются в Class Defaults `WBP_SettingsPage`.

В стартовом меню сохранение отключено; загрузка открывает выбранную запись игрового уровня. Внутри игры она применяет снимок без ухода в стартовую карту. Пока открыто общее меню, ввод движения и камеры заблокирован; закрытие возвращает управление. Сетевая страница в текущей игре предлагает сначала выйти в главное меню перед новым подключением.

Проверки после разделения: `Invenza.Frontend.MenuFlow` и `Invenza.Inventory.MenuLoad`. Структура страниц не создаётся в C++.

Упомянутые в исторических заметках исходники автотестов удалены по запросу владельца и не входят в текущую поставку. Для проверки используйте описанные игровые сценарии.
